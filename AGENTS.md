# Global Coding Instructions

## General principles

- Prefer simple, maintainable solutions over clever implementations.
- Do not introduce unnecessary dependencies.
- Preserve existing functionality unless the task explicitly requires changing it.
- Before modifying code, understand the existing architecture and conventions.
- Do not make unrelated changes.
- Explain significant architectural decisions briefly.
- Follow development professional best practices: code modularity, always comment the code, code should always be in English language.

## Testing

- Run relevant tests after making changes.
- If tests cannot be run, explain why.
- Add or update tests when changing behavior.

## Security

- Never hardcode credentials, API keys, tokens, or secrets.
- Validate external input.
- Follow existing security patterns in the project.

## Code quality

- Prefer readable code over overly compact code.
- Avoid duplication where practical.
- Use existing utilities and abstractions when appropriate.
- Keep functions/classes focused on a clear responsibility.
- Always comment the code.

## Git

- Do not create commits unless explicitly requested.
- Do not modify or delete unrelated changes made by the user.
